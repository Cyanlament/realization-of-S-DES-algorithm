# 用户指南

## 1. 环境与安装

需要 Python 3.10+。桌面程序使用 PySide6-Essentials 6.11.2，已在本机 Windows、Python 3.10.0 上验证。核心算法不依赖 Qt。C++ 仅用于独立交叉验证，日常使用不需要编译器。

Windows 双击根目录 `run.bat` 即可；首次运行会在本目录创建 `.venv` 并从 PyPI 安装依赖。已有环境可执行 `.venv\Scripts\python main.py`。

启动窗口会显示当前步骤；创建环境时优先使用 `py -3`，找不到合适版本再尝试 `python`。窗口打开后请保留启动控制台。启动失败会显示具体错误并保留窗口，同目录 `startup.log` 记录最近一次启动的输出。脚本使用 Windows CRLF 换行，Git 和编辑器配置会保留该格式。

Linux/macOS 使用 `python3 -m venv .venv`，随后 `.venv/bin/python -m pip install -r requirements.txt`，最后 `.venv/bin/python main.py`。桌面版需要图形会话和系统 Qt 所需的图形库；无桌面服务器可直接运行命令行。

## 2. 第一页：分组加解密

1. 密钥框输入恰好 10 位二进制数，如 `1010000010`。
2. 输入分组框填写恰好 8 位二进制数，如 `11010111`。
3. 点击“加密”，结果为 `10001100`；下方列出 K1、K2 和两轮中间值。
4. 将输入改成 `10001100`，点击“解密”，应得到 `11010111`。
5. “复制结果”复制输出分组，方便与其他组交换。

输入支持去除首尾空白，内部空格、非 0/1 字符、错误长度都会报错。失败时不会显示上一笔分组操作的结果。

## 3. 第二页：文本扩展

“明文编码”选择 ASCII 或 UTF-8。ASCII 严格限制在 U+0000 到 U+007F；中文需要 UTF-8。每个编码后的字节作为一个 8 位分组，使用同一个密钥独立加密，不填充。

明文框输入 `Hello, S-DES!`、密钥输入 `1010000010`，选择 Hex，点击“明文 → 加密”，得到：

```text
C4 F8 0D 0D 2F 99 62 4F 36 5F 50 4F 29
```

保留密文与密钥，点击“密文 → 解密”，明文恢复为原字符串。明文的空格、换行和空字符串均有测试覆盖。

密文可以使用三种**表示**，它们不改变算法：

| 格式 | 示例 | 说明 |
| --- | --- | --- |
| Hex | `C4 F8 0D` | 每字节两位十六进制，可含空白 |
| Base64 | `xPgN` | 严格 Base64，首尾空白可忽略，内部不允许空白 |
| 转义字节 | `\xc4\xf8\x0d` | 每字节固定 `\xHH`，适合观察不可打印字符 |

密文字节可能超出标准 ASCII 范围或是控制字符，因此直接把它当作可打印字符串会丢失信息。使用上述任意一种表示均可无损传递；更换格式后重新加密，或输入与所选格式相符的密文。

## 4. 第三页：暴力破解

每行填写一组同一密钥下的明密文，用空格分隔。输入：

```text
11010111 10001100
```

点击“遍历全部 1024 个密钥”，得到 3 个候选：`0110000000`、`1010000010`、`1011001010`。程序不会把第一个匹配误当成唯一正确密钥。

将 `evidence/known_pairs.txt` 中的五行全部粘贴到输入框再搜索，唯一候选为 `1010000010`。界面显示已检查数量、进度、开始时间、结束时间及高精度耗时。搜索运行于后台线程，支持停止；停止后结果明确标记为部分结果。1024 个密钥通常很快遍历完，可能来不及点击停止，这是正常现象。

已知对相互矛盾时会显示无匹配密钥。例如同时输入 `00000000 00000000` 和 `00000000 00000001`。

## 5. 第四页：碰撞分析

输入一个 8 位明文，点击分析。程序枚举全部密钥，按密文聚合并列出所有包含至少两个密钥的分组。摘要显示不同密文数、碰撞组数和最大候选数。对于 `11010111`，本实现得到 240 种密文、224 个碰撞组，最大组含 12 个密钥。

这与固定密钥下加密可逆没有矛盾：这里固定的是明文、变化的是密钥。

## 6. 命令行与外组交换

```bash
python -m sdes encrypt 11010111 --key 1010000010 --trace
python -m sdes encrypt "Hello, S-DES!" --key 1010000010 --text ASCII --format Base64
python -m sdes decrypt "xPgNDS+ZYk82X1BPKQ==" --key 1010000010 --text ASCII --format Base64
python -m sdes crack --pairs-file evidence/known_pairs.txt
python -m sdes collisions 11010111
python tools/verify_vectors.py evidence/cross_vectors.json
```

外组 JSON 格式为 `{"vectors":[{"key":"1010000010","plaintext":"11010111","ciphertext":"10001100"}]}`。验证器会同时验证加密和解密；存在不匹配返回非零退出码。填写外组记录时保留其原始文件，不修改对方结果以迎合本程序。

## 7. 常见问题

- 双击 BAT 后出现 `'xist'` / `'evel'` 等“不是内部或外部命令”：这是旧启动脚本换行格式错误，已改为 CRLF；请使用最新 `run.bat` 或重新解压更新后的提交包。
- 窗口未打开：查看同目录 `startup.log`，其中保存依赖检查、安装和实际 GUI 启动异常。
- `No module named PySide6`：使用安装依赖的同一个解释器，重新执行 `python -m pip install -r requirements.txt`。
- `python` 找不到：安装 Python 并加入 PATH，或把命令中的 `python` 换成已安装解释器的完整路径。
- `g++` 找不到：仅影响全量独立参考验证；常规桌面运行和 Python 单元测试仍可使用。安装 GCC/MinGW 或使用已有 `g++`。
- 解密结果不是合法文本：检查密钥、编码和密文表示。S-DES 不提供认证；错误密钥偶然得到合法文本也不代表结果可信。
- 与其他实现不同：先核对修改后的 S-box2、位序、S-box 行列索引和密钥累积左移顺序。
